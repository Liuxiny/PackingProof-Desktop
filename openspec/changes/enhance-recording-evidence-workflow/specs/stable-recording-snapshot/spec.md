## ADDED Requirements

### 需求:自动识别范围必须跟随有效放大范围
系统必须使用与当前运行时智能放大完全相同的中央裁剪矩形进行自动条码识别和引导框显示；禁止使用固定 2 倍或独立固定比例。未启用放大时，识别范围必须为完整画面。

#### 场景:用户调整放大倍数
- **当** 用户把有效放大倍数从 1.5 倍改为其他合法值
- **那么** 识别裁剪、主界面引导框和录像放大范围必须同时更新为同一个几何区域

#### 场景:用户关闭智能放大
- **当** 当前录像配置未启用智能放大
- **那么** 自动条码识别必须使用完整摄像头画面且界面不得继续显示旧的缩小识别框

### 需求:小条码识别必须保留原始像素
系统必须从未缩小的摄像头原始帧裁取条码候选，并对候选区域执行受限的多尺度和图像增强解码；禁止在候选定位前强制把整幅高分辨率图像缩小到固定最大尺寸而丢失远距离条码细节。

#### 场景:1080P或更高分辨率下识别远距离条码
- **当** 条码在有效识别范围内但在整幅画面中占比较小
- **那么** 系统必须使用原始分辨率候选区域尝试识别，同时保持最新帧覆盖旧帧且不形成无界队列

### 需求:自动识别必须经过身份和稳定性确认
系统必须在合法单号连续一致、条码候选运动低于阈值、清晰度合格且曝光稳定后才进入抓拍；禁止以单帧偶然解码直接开始录像。

#### 场景:面单仍在移动
- **当** 连续帧中的同一条码中心、尺度或角度仍明显变化
- **那么** 系统必须保持等待并提示用户稳定画面，不得抓拍或开始录像

#### 场景:同一条码稳定出现
- **当** 同一合法单号在规定窗口内通过连续确认且对应区域清晰、曝光和运动均合格
- **那么** 系统必须锁定该单号并进入最高分辨率抓拍阶段

### 需求:每个本机新录像必须先取得原始全分辨率照片
摄像头录像工作站创建的每个新录像段，无论由摄像头识别、扫码枪、网页联动或手动操作触发，都必须在视频开录前保存一张稳定、完整、最高可用原生分辨率照片。照片必须未经裁剪、旋转、数字放大、超分辨率或生成式修改；没有订单号也禁止跳过抓拍。

#### 场景:扫码枪触发录像
- **当** 扫码枪提交有效单号
- **那么** 系统必须跳过面单定位要求，但仍必须等待稳定的最高可用原生分辨率全图保存成功后才开始录像

#### 场景:手动无单号录像
- **当** 用户在没有订单号的情况下手动开始录像
- **那么** 系统必须保存当前摄像头稳定全图并与生成的录像记录绑定，不得运行条码或面单定位

#### 场景:连续扫码切换录像
- **当** 当前录像因新单号停止并准备开始下一段录像
- **那么** 下一段录像必须取得自己独立的新照片，禁止复用上一段录像的照片

### 需求:最高可用原生分辨率必须经过实际取帧验证
系统必须优先使用摄像头独立静态拍照能力；没有独立通道时必须临时使用驱动枚举且实际取帧成功的最高像素视频模式。拍照后必须恢复用户录像模式并等待有效首帧。

#### 场景:摄像头支持独立高分辨率拍照
- **当** 设备检测确认静态通道可以在不中断预览的情况下输出最高原生分辨率
- **那么** 系统必须优先使用该通道完成抓拍

#### 场景:摄像头需要切换分辨率
- **当** 设备没有可用独立静态通道
- **那么** 系统必须切换到已验证的最高原生模式、丢弃暖机帧、取得稳定照片，再恢复并验证录像模式

#### 场景:照片无法稳定获取或写入
- **当** 摄像头、驱动或存储错误导致照片未能完成
- **那么** 系统必须阻止静默开录并显示具体错误或持续稳定提示，禁止创建没有照片的新本机录像段

### 需求:照片必须与录像一一绑定并纳入容量计算
系统必须记录照片本地/网络路径、实际宽高、拍摄时间、摄像头信息、文件大小、哈希和抓拍状态，并把照片大小计入存储用量、保留预测和录像聚合资产。

#### 场景:照片保存成功
- **当** 稳定全分辨率照片原子发布完成
- **那么** 数据库必须在开始视频前把照片绑定到本次录像记录，后续查询不得把它关联到相邻录像

#### 场景:估算录像保留天数
- **当** 系统根据历史数据预测可保留天数
- **那么** 计算必须包含每条录像对应照片的实际平均大小
