## ADDED Requirements

### 需求:录制期间必须直接生成AAC音轨
系统必须在录制期间把受监控的 WASAPI 音频实时编码为 AAC-LC，并与视频写入同一可恢复临时容器；正常录制路径禁止生成 WAV 中间文件。最终 MP4 必须对视频和 AAC 音轨执行流复制，不得再次压制视频或音频。

#### 场景:正常音视频录制
- **当** 麦克风、编码器和视频录制均正常
- **那么** 临时录像必须已经包含可校验的 AAC 音轨，最终 MP4 封装必须使用音视频流复制

#### 场景:AAC输入无法建立
- **当** 配置要求录音但 AAC 输入或音轨初始化失败
- **那么** 系统必须明确阻止开录或报告本次录音失败，禁止静默生成看似正常的无声成品

### 需求:后处理必须等待连续空闲一分钟
系统必须持久化每段已结束录像的后处理任务，并且只有在抓拍、启动、录制和停止活动全部结束后连续空闲至少 60 秒才可开始大文件后处理。任何新的录像相关活动必须重置空闲计时。

#### 场景:一分钟内继续录制
- **当** 一段录像结束后 60 秒内开始新的抓拍或录像任务
- **那么** 系统不得开始 MP4 封装、完整哈希或网络大文件复制，并必须从新活动结束时重新计时

#### 场景:连续空闲满一分钟
- **当** 待处理队列非空且所有录像相关活动连续停止满 60 秒
- **那么** 系统必须选择队列中完成时间最新的任务开始处理

### 需求:待处理录像必须从新到旧且串行处理
系统必须按录像完成时间降序处理待办，每次最多处理一条；每完成一条后必须暂停 10 秒并重新检查是否出现录像活动。

#### 场景:存在多条待封装录像
- **当** 空闲门槛满足且队列中存在多个完成录像
- **那么** 系统必须先处理最新录像，成功或记录失败后暂停 10 秒，再决定是否处理下一条

### 需求:新录像必须抢占所有低优先级大文件I/O
MP4 封装、最终媒体校验、SHA-256/签名、网络归档和材料清理必须共享同一个可取消 I/O 闸门。抓拍或录像任务出现时，系统必须取消当前低优先级工作、保留源资产，并仅清理由当前操作证明拥有的不完整输出。

#### 场景:转换过程中开始新录像
- **当** FFmpeg 正在生成 `.mp4.writing` 时出现新的抓拍或录像活动
- **那么** 系统必须终止本次低优先级转换、保留源 MKV 和照片、删除本任务拥有的不完整输出，并在下一次连续空闲后重试

#### 场景:竞争任务已经发布有效目标
- **当** 失败任务进入清理时另一个任务已经成功发布同名有效目标
- **那么** 失败任务必须保留有效目标，禁止因源文件状态变化而删除其他任务的成果

### 需求:最终证明和归档必须以MP4与原始照片为准
系统必须在最终 MP4 和绑定原始照片均完成并校验后生成联合签名证明，并在证明成功后才允许网络归档发布。证明必须分别记录视频和照片的名称、长度及 SHA-256。

#### 场景:MP4完成但照片或证明失败
- **当** 最终 MP4 已发布但照片缺失、哈希失败或联合证明写入失败
- **那么** 记录不得标记为完整可归档，系统必须保留恢复所需源资产并明确提示

#### 场景:网络归档成功
- **当** MP4、照片和联合证明均复制到网络目标并通过长度和哈希验证
- **那么** 系统才可把聚合资产标记为已验证归档并按保留策略处理本地副本

### 需求:后处理队列必须跨重启恢复
系统必须把任务状态和当前阶段存入 SQLite，应用退出时禁止为清空队列而强制执行大文件转换；重启后必须恢复未完成任务并重新遵守 60 秒空闲门槛。

#### 场景:有待处理录像时关闭程序
- **当** 用户关闭程序而队列仍有 MKV、照片或未完成归档
- **那么** 系统必须安全停止当前任务并持久化状态，下一次启动后不得丢失或误删这些资产
