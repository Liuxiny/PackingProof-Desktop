## 为什么

当前摄像头条码识别在正常工作距离下容易因小条码、模糊和曝光波动失败，录像又缺少与每段视频一一绑定的高分辨率现场照片；同时 MKV、WAV、MP4 封装、证明生成和网络归档会产生多次大文件 I/O，并且桌面回放缺少照片查看和安全的人工删除入口。需要把识别、抓拍、录像后处理和回放证据管理统一成一条以录像优先、可恢复且适合 N100 设备的工作流。

## 变更内容

- 让摄像头条码识别范围始终与当前智能放大裁剪范围一致，不再固定为 2 倍或固定比例，并保留扫码枪、手动和其他触发方式。
- 改进条码识别的原始分辨率候选裁剪、多尺度预处理、连续确认、清晰度和画面稳定性判断，避免在识别前缩小远距离小条码。
- 所有录像在开始前必须取得一张稳定、未裁剪、未数字放大、未生成式增强的摄像头最高可用原生分辨率全图；自动识别模式先确认单号，其他模式不执行面单定位，但同样必须抓拍。
- 将原始抓拍照片与录像记录一一绑定，缩略图仅由原图等比例缩小；桌面回放支持点击缩略图查看原图。
- 音频在录制期间直接编码为 AAC，正常路径不再生成 WAV；最终 MP4 对视频和 AAC 音轨执行流复制。
- 录像后处理改为持久化空闲队列：连续空闲满 1 分钟后按完成时间从新到旧处理，每完成一条暂停 10 秒；新录像或抓拍任务可抢占转换、校验、签名和网络归档。
- 最终 MP4 和原始抓拍完成后再生成联合防篡改证明并进入网络归档，成功前保留可恢复源文件。
- 桌面回放中为每条录像提供带二次确认的永久删除按钮，统一删除本地和网络视频、照片、证明及当前任务拥有的临时文件，并保留删除审计记录。
- 网页回放继续保持只读；不提供网页删除 API 或按钮。未来若增加网页删除，必须另设默认关闭的权限开关、管理员验证和幂等防重复机制。
- 将“高级模式”全局开关移到设置窗口左侧固定区域，使其可从任意设置页面访问并继续持久化。

## 功能 (Capabilities)

### 新增功能

- `stable-recording-snapshot`: 定义跟随放大范围的摄像头识别、稳定性判断、最高可用原生分辨率抓拍，以及每条录像必备原始照片。
- `idle-media-finalization`: 定义实时 AAC、录像优先的空闲后处理队列、MP4 无损封装、联合证明和网络归档顺序。
- `playback-evidence-management`: 定义桌面照片缩略图、原图查看、本机安全删除和网页只读边界。
- `global-advanced-settings-mode`: 定义设置左侧全局高级模式开关的范围、即时行为和持久化。

## 影响

- 摄像头采集、条码识别、智能放大、录像启动状态机和首次使用检测。
- FFmpeg/音频采集参数、MKV/AAC/MP4 后处理、后台 I/O 调度和异常恢复。
- SQLite 录像记录、照片元数据、转换/删除任务状态和删除日志。
- 本地临时目录、网络归档、空间预测、保留清理和防篡改证明格式。
- WPF 设置窗口、桌面回放窗口、图片查看器以及只读 Web API/页面返回模型。
- N100 8GB 设备、不同 UVC 摄像头最高分辨率切换和真实面单距离的性能与兼容性验证。
