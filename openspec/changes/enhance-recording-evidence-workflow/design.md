## 上下文

当前程序把摄像头原始帧交给 OpenCV/ZXing 识别，并把中央固定比例区域作为主要条码识别范围；智能放大则使用另一套可配置裁剪比例。录像视频经 FFmpeg 写入 MKV，WASAPI 音频另写 WAV，停止后再转成带 AAC 音轨的 MP4。证明、网络归档、回放列表和保留清理目前只把视频作为主要生命周期对象。

本变更把“录像证据”扩展为一条录像、对应的原始全分辨率抓拍和联合证明。摄像头录像工作站上的每个新录像段，无论由摄像头条码、扫码枪、网页联动还是手动按钮触发，都必须先完成稳定抓拍。自动识别模式仅额外负责在与放大范围相同的区域确认单号；照片本身始终保存完整原图，不定位、裁切、旋转或生成式增强。外部设备已存在的历史录像和无法访问本机摄像头的查看工作站不反向补拍。

目标设备包含 Intel N100、8GB 内存和性能/驱动差异较大的 UVC 摄像头，因此识别不能堆积帧，最高分辨率拍照必须探测实际能力，所有录像后大文件 I/O 必须让位于抓拍和录像。

## 目标 / 非目标

**目标：**

- 让自动条码识别区域与实时智能放大裁剪区域共享同一个几何计算和可视化。
- 在正常安装距离提高小条码识别率，并以多帧身份、运动、清晰度和曝光信号确认画面稳定。
- 为摄像头工作站创建的每个新录像段生成一张稳定、完整、最高可用原生分辨率的原始照片。
- 将照片作为录像生命周期资产纳入数据库、空间预测、联合证明、网络归档、历史查看和删除。
- 在录制期间直接产生 AAC 音轨，并在连续空闲后以可抢占的单任务队列完成 MP4、证明和归档。
- 在本机桌面回放提供照片缩略图、原图查看和带二次确认的并发安全删除。
- 保持网页回放只读。

**非目标：**

- 不定位面单边界，不生成透视校正、旋转后的“正视面单图”。
- 不使用 OCR 代替条码单号，不对证据照片做超分辨率、生成式修复或内容补全。
- 不为已有录像、外部上传录像或无摄像头工作站伪造抓拍照片。
- 不在网页提供删除按钮或删除 API。
- 不改变用户固定编码器不可用时阻止开录的策略。

## 决策

### 1. 放大裁剪与识别裁剪共享几何源

新增单一的运行时裁剪计算：有效放大倍数为 `scale` 时，中央区域宽高分别为原始帧宽高除以 `scale`；未启用放大时使用完整画面。主界面识别框、条码候选裁剪和智能放大必须使用同一个矩形结果，禁止分别保存比例常量。

自动识别先在低成本图像上寻找条码候选，再从未缩小的原始帧裁取候选区域执行灰度、局部对比度、轻度锐化、二值化和有限多尺度解码。工作线程继续采用“只保留最新一帧”的有界模型。相比整幅高分辨率图像反复尝试所有滤镜，这能保留小条码细节并限制 N100 的 CPU 和内存开销。

### 2. 抓拍是录像启动状态机的必经阶段

录像触发统一进入 `Requested -> WaitingForStableFrame -> CapturingSnapshot -> SnapshotPersisted -> StartingVideo` 状态机。自动识别触发在进入稳定阶段前还需要同一合法单号的连续确认；扫码枪、网页联动和手动触发不执行面单或条码定位，但仍执行全画面稳定抓拍。没有订单号不再跳过照片。

稳定性使用多信号质量门，而不是单一整帧差：

- 自动识别模式跟踪条码候选在连续帧中的中心、尺度和角度，并要求内容一致；
- 其他模式计算完整画面的稳健光流/差分、清晰度和曝光变化；
- 两种模式都从短时帧组中选择清晰度最高且满足曝光要求的帧；
- 摄像头重新配置后丢弃暖机帧，等待自动曝光和对焦重新稳定。

如果稳定照片无法产生或无法持久化，系统禁止静默开始视频，并持续给出“请保持画面稳定”或具体摄像头/存储错误。这样保证“每个新录像都有照片”的不变量，而不是事后补一张无关画面。

### 3. 最高可用原生分辨率按设备能力分层

设备检测阶段记录摄像头的独立静态拍照能力和视频能力：

1. 优先使用不会中断当前预览的最高原生静态拍照模式；
2. 无独立拍照通道时，临时切换到经过实际取帧验证的最高原生视频分辨率；
3. 拍照后恢复用户配置的录像模式，等待首个有效帧再启动 FFmpeg。

“最高可用”指驱动枚举且在限定时间内成功输出稳定帧的最高像素模式，不采用驱动只报告但无法实际取帧的模式。照片保存为高质量 JPEG，保留完整视野和实际像素尺寸，不应用智能放大裁剪或水印烘焙；拍摄时间、订单标识、摄像头、分辨率和哈希写入数据库/证明元数据。

### 4. 照片是录像聚合资产，缩略图只是缓存

`VideoRecords` 增加本地/网络照片路径、拍摄时间、宽高、照片哈希、抓拍状态和错误信息。缩略图不作为独立证据文件，仅从原图等比例解码到目标尺寸并写入 `%LOCALAPPDATA%` Web/桌面缓存；清除缓存后可重建。

录像历史解析一个聚合资产时必须选择已验证网络照片优先、本地照片兜底，规则与视频一致。空间统计、保留期限和删除操作包含照片实际大小。联合证明在最终 MP4 与原始照片都存在后生成，载荷分别记录两个文件的名称、长度和 SHA-256。

### 5. 音频实时 AAC，最终 MP4 只做流复制

保留 WASAPI 采集、通道选择、断流检测和时间线统计；规范化后的 PCM 通过第二输入管道交给 FFmpeg，在录制期间编码成 AAC-LC 并写入同一临时 MKV。正常路径不生成 WAV 或独立 AAC 历史文件。最终封装对视频和音频都使用 `copy`，避免停止后再次进行音频编码。

如果设备/FFmpeg 无法建立 AAC 音轨，沿用明确阻止开录或标记录音失败的策略，禁止静默生成看似正常的无声成品。

### 6. 所有大文件后处理共用录像优先 I/O 闸门

SQLite 保存持久化后处理任务。最后一次抓拍/录像活动结束后连续空闲 60 秒，调度器才按 `EndTime DESC` 选择最新任务。每次只处理一个录像聚合资产，完成后等待 10 秒并重新检查活动状态。

I/O 闸门覆盖 MP4 封装、媒体校验、SHA-256/签名、网络复制和材料清理。抓拍等待、摄像头切换、启动、录制、停止阶段都视为高优先级活动。新活动出现时取消当前低优先级进程；源 MKV、照片和已发布结果必须保留，只能在持有录像生命周期锁时删除本任务创建的 `.writing` 文件。被抢占任务恢复为待处理，并在下一次连续空闲 60 秒后重试。

完成顺序固定为：验证临时音视频 -> 流复制生成 `.mp4.writing` -> 校验最终 MP4 -> 原子发布 MP4 -> 生成视频+照片联合证明 -> 入队网络归档 -> 验证网络资产 -> 清理源文件。应用退出不强制清空队列，重启后从 SQLite 恢复。

### 7. 桌面删除使用持久化删除意图

桌面列表项携带录像记录 ID，删除按钮不触发行选择。用户二次确认后先在数据库写入删除意图，再在 `VideoLifecycleCoordinator` 的同一记录锁内重新读取最新状态、停止该记录的回放、取消后处理/归档并解析确切资产所有权。

删除覆盖本地和网络视频、原始照片、联合证明以及能证明由该任务创建的临时文件；缩略图缓存按记录 ID 清除。网络不可用时记录保持“等待网络删除”，后台恢复后幂等重试；只有已知副本都删除后才完成软删除和审计记录。当前录制、抓拍、封装或来源不明确的记录禁止直接删除。

网页可以返回照片缩略图和原图只读地址，但路由表禁止新增 DELETE 方法；现有访问密钥不能授权删除。

### 8. 高级模式开关成为左侧全局控件

设置窗口左栏模板拆分为导航区和固定底部操作区。“高级模式”切换位于左侧、关于入口上方，不属于任何 TabItem。开关继续绑定持久化配置，并立即控制各页面专业参数的可见性；关闭时若焦点位于将隐藏的控件，焦点转移到当前页面首个可见控件。

## 风险 / 权衡

- [摄像头最高分辨率切换可能耗时、改变视野或无法恢复] -> 首次检测必须实际取帧并记录模式；抓拍后验证录像模式和首帧，失败时阻止开录并给出可操作错误。
- [把照片设为强制资产会增加开录延迟] -> 使用独立静态通道优先、短时帧组择优和设备级缓存；界面明确显示“等待稳定/正在拍照/恢复摄像头”。
- [整幅画面稳定判断可能受背景人员移动影响] -> 使用稳健统计、中心权重和清晰度择优；阈值按分辨率归一化并通过真实设备标定。
- [实时 AAC 的第二输入管道增加同步复杂度] -> 使用统一单调时钟、受控有界队列和现有音频间隙统计；增加启动失败、音频中断和 A/V 时长回归测试。
- [最新优先可能让旧任务长期等待] -> 只有完全空闲时处理队列，并显示积压数量/空间预测；在无新任务时队列最终会耗尽。
- [网络离线时人工删除不能立即删除远端] -> 持久化删除意图、明确显示待删除状态并在网络恢复后幂等完成，禁止误报成功。
- [联合证明格式变化影响旧证明] -> 新证明使用新版本载荷；旧录像继续按原视频证明规则读取，不做破坏性迁移。

## 迁移计划

1. 以可空字段扩展录像记录和任务状态，旧录像保持“无抓拍照片”。
2. 增加新版本联合证明读取器，同时保留旧版视频证明验证。
3. 先在影子模式记录新识别/稳定指标，不触发录像，使用 N100 和真实摄像头校准。
4. 启用强制抓拍状态机和照片历史展示，再启用实时 AAC/空闲后处理。
5. 最后开放本机人工删除；验证网络离线、任务抢占和并发失败清理后再发布。
6. 回滚时停用新入口和调度器，但保留新增数据库字段、照片和待处理任务，禁止回滚逻辑删除未知资产。

## 待确认问题

- 真机验收应记录各目标摄像头从触发到照片落盘、再到录像首帧的最大可接受延迟；规范先要求明确显示并阻止无照片开录，不预设所有设备共用的硬编码秒数。
