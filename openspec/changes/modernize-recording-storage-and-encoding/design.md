## 上下文

应用是 .NET 8 WPF 单机程序，使用 OpenCvSharp 采集帧、FFmpeg 编码、SQLite 保存录像索引，并通过内置 Web 服务提供历史播放和剪辑。当前 `StorageLocationResolver` 返回一个最终路径，FFmpeg 直接向该位置写入；`VideoRecords` 只保存 `FilePath`，清理器也据此直接删除文件。网络共享离线会因此进入录像主链路，历史入口也缺少网络/本地双路径解析。

目标部署包含 Intel N100、8GB 内存等低功耗设备。所有检测、签名和网络传输必须使用有界内存及后台顺序 I/O，不能缓存整段录像或并行压满编码器。

## 目标 / 非目标

**目标：**

- 保证网络离线时录像仍能可靠写入本地，并在恢复后自动完成可校验归档。
- 建立一个统一的录像物理路径解析和生命周期状态模型。
- 以自然日保留规则、可选容量上限和安全预留空间管理本地文件，并基于历史数据预警。
- 只向用户展示实际试编码成功的完整编码器，固定选择失效时失败可见。
- 用短时主动测试和真实录像复检给出可执行推荐。
- 以低开销动态水印和最终签名证明录像完整性。
- 完全移除桌面自动更新的联网、下载和安装链路。

**非目标：**

- 不在应用内保存或管理网络共享凭据。
- 不自动控制摄像头曝光、快门或厂商私有驱动设置。
- 不保证任意浏览器直接解码 H.265/AV1；Web 端继续通过转码解决兼容性。
- 不在本变更中构建云端密钥或中心证书服务。
- 不允许性能推荐静默覆盖用户固定配置。

## 决策

### 1. 网络路径是归档目标，不是录制工作目录

网络存储启用时，FFmpeg、WAV、封装和签名均在一个用户配置的全局本地缓冲根目录完成。完成文件进入 SQLite 持久化归档队列；服务复制为网络端唯一 `.uploading` 文件，比较长度和 SHA-256 后在同目录原子改名。

相较直接写网络路径，该方案隔离网络抖动；相较先写系统临时目录，全局用户路径让容量和保留策略可见、可控。

### 2. 数据库保存物理双路径和显式状态

`VideoRecords` 增加本地路径、网络路径、归档状态、哈希、证明文件、重试与错误字段。保留旧 `FilePath` 用于平滑迁移，但所有新访问入口通过 `VideoFileResolver` 获得有效路径。归档状态使用稳定字符串：`LocalOnly`、`Pending`、`Copying`、`Verified`、`Failed`、`Conflict`、`LocalDeleted`、`Unavailable`。

### 3. 发布、校验和清理共享每条录像生命周期锁

归档服务以录像 ID 为所有权键。网络正式文件只在临时复制校验成功后发布；数据库提交 `Verified` 后，本地文件才具有清理资格。清理器在同一生命周期锁内重新读取状态并验证源/目标关系，失败任务不得删除其他任务已发布的文件。

### 4. 日期是默认策略，容量是可选附加上限

全局最长保留天数默认 90，最小 15，不设最大值。录像最大占用默认禁用；启用后与日期策略共同生效，任一达到即可按最旧优先清理。磁盘安全预留空间是独立硬底线，继续由 `StorageSpacePolicy` 统一计算。

已验证网络归档的本地副本采用更短规则：以本机自然日保留今天和昨天。未归档文件遵循全局日期/容量设置；清理前优先归档并记录醒目风险与删除原因。

建议保留天数由最近有效历史的日均录像量、当前可用容量和安全预留空间计算。建议值向下取整且不得低于 15；它只填充建议/快捷操作，不自动覆盖当前值。

### 5. 完整编码器是配置原子单位

用稳定编码器 ID（如 `h264_qsv`、`hevc_nvenc`、`libsvtav1`）持久化固定选择，另保留 `auto`。探测先读取 FFmpeg 编码器列表，再执行短样本试编码；只有成功项进入列表。自动模式可在开录前选择，固定模式任何失败都阻止开录且不回退。

### 6. 性能检测采用分层、有限候选测试

摄像头驱动能力按分辨率/帧率配对。性能检测优先测试当前组合和少量降级候选，采集与编码使用有界队列，记录输入帧率、输出帧率、丢帧、CPU 和文件可解析性。推荐优先稳定、硬件编码和 H.264 兼容性。

第一次真实录像复检由配置指纹触发。分辨率必须匹配，平均帧率至少为目标 90%，严重丢帧不超过 10%，时长误差不超过 `max(1 秒, 5%)`。通过后保存指纹，避免重复提示。

### 7. 动态证明码与最终签名分层

每秒用 HMAC-SHA256 对录像会话、时间片、订单信息和前一证明码计算一次，截断为可读大写字母数字水印。录像完成后顺序计算最终文件 SHA-256，生成 `.proof.json`，并使用受 Windows 用户保护的设备密钥签名。哈希在后台低优先级线程执行，禁止读取整文件到内存。

### 8. 启动器降级为纯启动器

删除桌面端自动检查、提示、下载、暂存、安装和回滚逻辑，以及自动 AppPatch 发布链路。启动器只负责定位并启动主程序。手动完整包/手动更新包仍可由用户主动获取。

## 风险 / 权衡

- [未归档录像达到用户期限后可能丢失] → 提前预测和持续告警、优先上传临近期限文件、保留数据库删除记录和明确原因。
- [UNC 存在性检查可能长时间阻塞] → 后台健康检查、短超时和状态缓存；UI 请求不直接同步探测 UNC。
- [网络端不支持可靠替换语义] → 临时文件与正式文件同目录，校验后改名；冲突时不覆盖。
- [签名密钥丢失导致旧录像无法重新签名] → 证明文件保存公钥标识；验证区分“签名无效”和“验证密钥缺失”，禁止重新签名旧录像。
- [主动性能检测耗时或发热] → 限制候选数量、单项短测、允许取消并在录制期间禁用。
- [超大保留天数造成磁盘压力] → 不限制输入，但持续显示预计可保存天数和安全预留线前的硬停止行为。
- [旧单路径数据语义不明确] → 迁移时根据路径类型分类，原字段保留一个版本周期并提供诊断日志。

## 迁移计划

1. 增加配置字段并规范化旧值：最长保留 90 天、最短校正为 15；最大占用默认关闭；旧最大时长分钟值转换为秒；旧 GPU/编解码组合映射为完整编码器或 `auto`。
2. 以幂等 `ALTER TABLE` 增加录像归档和证明字段，不删除 `FilePath`。
3. 本地旧路径迁移为 `LocalFilePath/LocalOnly`；网络旧路径迁移为 `NetworkFilePath/Verified`，无法确认存在时标记 `Unavailable` 但不删除记录。
4. 先启用统一路径解析，再启用归档队列，最后切换清理器，避免中间版本误删。
5. 移除自动更新后更新打包和文档；旧更新缓存不自动递归删除，只在明确、安全的缓存目录中做一次可记录清理。

回滚时保留新增列和本地文件；旧版本仍可读取兼容 `FilePath`，但不得让已迁移网络队列在旧版本中自动清理。

## 开放问题

无。全局最长保留天数按用户最终确认固定为默认 90 天、最短 15 天且不设上限。
