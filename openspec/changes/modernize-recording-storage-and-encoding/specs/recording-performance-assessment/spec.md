## ADDED Requirements

### 需求:性能检测必须使用真实采集和编码
系统必须在设备与画面界面提供性能检测按钮，基于摄像头真实分辨率/帧率组合和实际编码测试返回分辨率、帧率及完整编码器推荐。

#### 场景:N100执行性能检测
- **当** 用户点击性能检测且未在录像
- **那么** 系统以有界内存完成短时测试并显示测量值、推荐配置和应用入口

### 需求:性能检测必须区分采集和编码瓶颈
系统必须分别测量输入帧率与编码输出，禁止把曝光、驱动或 USB 导致的采集低帧率错误归因于编码器。

#### 场景:摄像头输入已低于目标
- **当** CPU负载正常但摄像头输入帧率低于目标
- **那么** 系统提示检查光线、自动曝光、驱动或 USB 带宽

### 需求:第一次真实录像必须复检
摄像头、分辨率、帧率或编码器变化后，第一段成功录像必须验证分辨率、平均帧率、丢帧、时长、编码格式和文件可解析性。

#### 场景:真实录像未达到帧率
- **当** 平均帧率低于目标 90% 或严重丢帧超过 10%
- **那么** 系统显示实测差异和推荐配置，并提供进入对应设置且预填推荐值的按钮

#### 场景:真实录像达标
- **当** 分辨率匹配、帧率及丢帧达标、时长误差不超过 `max(1秒,5%)` 且文件可解析
- **那么** 系统记录配置指纹并不显示推荐提示
